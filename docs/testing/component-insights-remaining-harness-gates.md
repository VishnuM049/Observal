# Remaining component-insights gates: Cursor, Codex, Kiro

**2026-10-17; stacked draft PR #3.** These are *conditional engineering estimates*, not support promises or evidence of zero use. They cover one tested version/scope at a time, including sanitized tests and isolated live acceptance, **after** necessary account or IDE access is available. Upstream product changes and CI/human-review time are not estimable. The verified-presence and permissions contract remains on draft #1779. No original home, original checkout, production endpoint, raw prompts, arguments, results, tokens, or transcripts were used as PR artifacts.

## New native controls and stop conditions

| Runtime | Controlled finding | Decision before an opt-in |
| --- | --- | --- |
| **Kiro CLI 2.32.0**, isolated tracked project stdio pin | An inline v2-agent `preToolUse` hook receives native `tool_name: @matrix-mcp-probe/ping` and `session_id`; a *successful* inert call additionally fires `postToolUse` with that same alias and writes an independent server marker. The native four-line session still calls its tool only `ping`, but contains a linked `toolResult` with `status: success`. With noninteractive approval denied, `preToolUse` fired, `postToolUse` did not, and the native result was `error`. A two-line no-tool session fired neither tool hook. Fresh successful/no-tool sessions automatically reached the loopback warehouse with a verified MCP mapping before reconcile. The hook input has **no tool-use ID or explicit result status**, and its alias/outcome were not part of the canonical session source. | This is a promising **native hook signal**, **not** a published use cell. A transient probe marker, a verified pin, or a generic transcript `ping` cannot be matched as a complete source call. Do not attribute multiple same-tool calls by order/time or count a no-hook session as zero. |
| **Cursor Agent 2026.10.14-941492e**, isolated tracked project stdio pin | Existing controls established automatic project-root delivery and verified presence; persisted JSONL kept only `GetDynamicTools` / `CallDynamicTool` attempts, not success. Current Cursor documentation describes `beforeMCPExecution` and `afterMCPExecution` inputs containing `mcp_server_name`, tool, and a full `result_json` (which must **never** be saved by Observal). We added an **isolated scratch-only** shape probe and tried a new CLI run, but the temporary Cursor profile is no longer authenticated: it stopped before a session or hook event. The probe hooks were removed after this unsuccessful control. | Documentation for the current product is a lead, **not** proof these hooks fire with that shape in the installed CLI build. A fresh same-account login **in the temporary home** and accepted/denied/no-tool native controls are required. No Cursor activity extractor or denominator is enabled. |
| **Codex CLI 0.163.0**, skills and registry hooks | Across the recorded isolated skill runs, native `event_msg` items are `UserMessage`, `AgentMessage`, `Reasoning`, and tool events; there is no structured `SkillLoaded`/`SkillInvoked` item. A rooted developer inventory establishes project availability only. A pasted `$skill` mention or a SKILL.md file read can imitate apparent invocation. Scratch native `Stop`/`PreToolUse` hook completion was visible to the CLI, but the tested rollout did not persist a registry hook's configured command plus its execution outcome. | Keep skill loads/invocations and registry-hook runs **null/unsupported**, not zero. The verified MCP `McpToolCall` cell is independent of those signals. |
| **Kiro IDE 1.3.11**, separate from CLI | Standalone v1 hooks were registered, but no prompt/Stop marker appeared and the two new sessions reached the warehouse **only after manual reconcile**. The isolated IDE log contains `hooks.v2.executionDisabledUntrustedWorkspace` during the initial control. A later trusted-workspace control still did not establish hook execution or pre-reconcile delivery. | Registration, manual recovery and the later trust action cannot prove automatic delivery. Require a fresh, restarted trusted IDE workspace with hooks visibly enabled and a marker plus warehouse checkpoint **before** reconcile. Do not reuse CLI 2.32.0 hook or call conclusions for IDE 1.3.11. |

The temporary Kiro CLI probe used an agent profile whose tool list contained **only** the inert MCP server. `--trust-all-tools` was needed for the successful noninteractive control; the narrower `--trust-tools=@matrix-mcp-probe` did not grant approval in this CLI. It is **not** a proposed production setting. The probe hook script recorded only structural field names, the alias, and a one-way session digest in private `/tmp` files; it recorded no tool input/response. The original profile hooks were restored afterward. Cursor's test hook and the user-authenticated home were likewise confined to temporary paths. The current published matcher deliberately still returns `unsupported` for Kiro and Cursor.

| Cell | Shortest viable evidence path | Estimate *if the prerequisite works* | If it does not |
| --- | --- | --- | --- |

Check session/generation binding, result semantics, duplicate/partial events and scope shadows. If native hooks really run, design an **opt-in, sanitized, bounded, durable hook-to-session source** with source revision, version, installation hash, and a positive coverage heartbeat. The live stream or an approval/attempt is not a substitute. An explicitly labelled *attempt diagnostic* would need a separate lower-trust contract and must not use the verified-use denominator. |

### Required work before any PR readiness change

1. Obtain a fresh **temporary-home Cursor login** without copying credentials from the original home; preserve its `sessionEnd` hook while running only sanitized native hook probes. The unmodified original checkout and `internal.observal.io` remain off limits.
2. Obtain a human-operated **trusted/restarted Kiro IDE** control. Inspect *execution*, not registration, then compare pre-reconcile warehouse state. Keep CLI/IDE runtime facts separate.
3. Choose a hook-evidence source design only after the native Cursor/Kiro controls, including authenticated session association, no-tool coverage, retry/replay, collision and missing-event behavior. A positive-only hook marker cannot be used as a usage-rate denominator. Never upload hook stdin, model output or tool arguments/results.
4. Run the applicable Linux full suite and matrix CI, audit the diff/screenshots and permissions, and obtain accountable human review of both stacked draft #3 and upstream draft #1779. The local focused suite and a loopback report do not make either PR ready.
