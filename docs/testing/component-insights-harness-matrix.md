# Component Insights harness matrix: Codex skill evidence and bounded MCP calls

This work is **stacked on draft #1779**, not a replacement for its verified-only installation contract. [Current status](component-insights-matrix-roadmap.md) and the [remaining per-cell evidence gates and estimates](component-insights-remaining-harness-gates.md) are tracked separately. Discovery used temporary harness homes and an isolated loopback-only Compose project. No historical installation was inferred from current configuration, a transcript tool name, a skill mention, an Agent pin, or a manual reconcile. Raw sessions, credentials, arguments, prompts and provider responses are not fixtures or PR artifacts.

## Executed-error classification correction (isolated, not release acceptance)

A later Codex 0.163.0 native stdio/HTTP control produced `event_msg.item_completed.McpToolCall` with `status=failed`, a non-null `result`, and `result.isError=true` **after the inert server ran**. The earlier extractor rejected that real error despite accepting a synthetic `completed` + `isError=true` shape. The corrected extractor accepts the observed `completed` + `isError=false` success and `failed` + `isError=true` executed-error pairs; a failed call with no result still makes the session unsupported, not a zero or an error. A sanitized real-shape fixture, matcher collision/privacy tests and a mocked projection check exercise the new result state. Private native 0.163.0 error rollouts pass the corrected extractor; 0.164.0 remains outside its version gate. The dedicated loopback API/worker images were rebuilt and the worker classified a sanitized executed error and a denied call correctly. **This was not a fresh registry-install-to-warehouse error report or browser acceptance run**; historical 20/4/11 figures above remain success-only. Other versions, registry-backed HTTP installs, pinned Linux CI and human review remain open.
